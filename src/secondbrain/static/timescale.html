How the data is laid out

Four ideas do all the work. Each block below is a real chunk in the database right now.

HypertableA normal SQL table that TimescaleDB splits into time chunks automatically. You query one table; it only reads the chunks you need.
ColumnstoreFinished chunks are compressed column by column. Similar values sit together, so they shrink many times over and still answer SQL.
Continuous aggregateHourly and daily totals the database keeps up to date as orders arrive, so a question over a year reads hundreds of rows, not millions.
SQL watcherEvery simulated day, plain SQL prices the sales lost to empty shelves and finds products out of stock for days; every hour it checks each store against its platform. Findings go out over MQTT.
